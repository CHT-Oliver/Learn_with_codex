# 极速备考：先测后学

仅在 SKILL.md 的模式路由命中时使用。将目标限定为本轮考点和题型的独立解题能力，不承诺考试分数或长期迁移能力。继续使用 mastery-rubric.md 的五级评价和 teaching-playbook.md 的纠偏方法，不新增第六级。

## 1. 建立范围与时间预算

- 复用上下文中的课程、资料、时间和目标；只一次性追问会改变路径的缺失信息。未给时间时声明暂按 20 分钟规划，可随时修改；不要等待确认才开始。
- 优先从用户提供的讲义、题目、考纲提取考点，记录文件名及页码/章节、要求的题型、前置依赖。只有资料明确支持时才能写考试权重或必考；否则标记权重未知。
- 没有真实课程资料时，明确写“示例考点，不代表你的课程考试范围”，可先运行示例。不把通用教材知识当作本校要求，不为了搜集资料拖延诊断。资料不可读或范围有缺页时列出未知部分。
- 建立考点表：ID｜来源定位｜目标表现｜前置｜优先级依据｜状态｜证据。覆盖范围大时分批处理，所有未测点保留为未测，禁止由一个考点外推整个章节。
- 默认将预算的约 20% 用于诊断、60% 用于补弱、20% 用于变式验证和收束；这是可调整的教学预算，不是实测耗时。超短预算时缩小范围，仍保留验证。没有可靠计时工具时使用估计时长，不能声称精确计时。

## 2. 先诊断，再决定是否讲

首批通常 2–4 道短题，每题可有少量子问，覆盖本批考点。题目出现时不附答案、提示或讲解；等待学生真实回答，禁止代答后宣布掌握。一次可批量诊断多个点，补讲仍一次只推进一个薄弱能力。

对每个拟跳过的点要求两种互补证据：解释/复述机制，加改错/变式应用。可来自同一复合题的不同子问，但不能把同一个选择结果重复计数。至少一个子问改变条件或要求指出边界。两者均须独立正确、理由成立且无核心误解；选择蒙对、自评会了、照抄答案、提示后答对均不足。批量题的每个子问分别评分，不能用总分掩盖薄弱点。

| 状态 | 判定 | 下一步 |
|---|---|---|
| 未测 | 没有相关作答 | 诊断；来不及时明确延期 |
| 待确认 | 仅一种有效证据、答案含糊或疑似猜测 | 最多追加一题针对性确认，仍不清楚则按薄弱处理 |
| 薄弱 | 核心机制错误或不能独立应用 | 最小前置补齐，再短讲练习 |
| 本轮可跳过 | 两种有效证据达标，覆盖当前目标 | 跳过该点讲解、示例和重复基础练习 |
| 补弱后通过 | 补弱后解释正确且独立变式通过 | 停止重复训练；保留证据 |

“本轮可跳过”是调度状态，不是五级掌握等级。按实际证据记录 Level 1–5 或证据不足；常见解释加改错只能支持 Level 3，不自动评为 Level 5。若课程要求设计题，诊断也必须覆盖设计要求。历史证据须有具体作答、相同目标及无冲突记录；范围变化、证据过旧或后续答错时降为待确认并复核。用户坚持跳过时遵从，但记为“用户跳过/未验证”，不标掌握。

## 3. 只补当前缺口

按资料明确的重点、前置依赖和预计补齐成本安排薄弱点。权重未知时优先补阻塞其他题的前置，说明这是教学排序。对每点执行：

1. 给出约 100–200 字的短讲，直接解释本次错误；避免整章重讲。
2. 给一张小状态图、对照表或时序示例；只有有助于理解才加入交互组件，不要求学生先操作多轮 UI。
3. 给一道针对性练习并等待作答。练习允许提示，但标明提示证据，不能据此通过。
4. 换条件给一道无提示变式题，要求结论及理由；不重复原题答案。结合独立解释证据判断是否通过。

同一点连续两次验证失败，停止原样刷题，按 teaching-playbook.md 定位最小前置或换例子；时间不够则保留薄弱状态及下一步。若后续综合题暴露已跳过点的误解，重新打开该点。默认不安排与考试目标无关的代码项目、长笔记抄写、学习方法问卷或逐步确认；变式解答本身就是微产出。

## 4. 收束与记录

最后的变式可以兼作结束验证，不再为形式额外加一轮考试。全点已通过诊断时可直接收束；无证据不足或冲突时不重复考试。预算耗尽时停止新增教学，列出未测和未通过内容，不以压缩时间为由降低通过标准。

遵循 SKILL.md 的文件规则，复用 mastery-check 和 mistakes-log 模板；可将本轮记录合并到一个 `study/<topic>-mastery-check.md`，不要求学生额外填写表格。用户要求仅聊天时仅在对话记录。

记录模式、资料范围、计划/实际或估计时间、每点目标、初始状态、题号与真实作答摘要、证据类型、是否提示、五级判断、最终状态、跳过理由、残留风险和下一次任务。保留历史证据，不用新结论覆盖原始错误。

分别汇报：已诊断覆盖率（有作答的考点/范围内考点）、本轮达标率（可跳过或补弱后通过/范围内考点）、未测点。讲过不等于覆盖验证。交互次数按需要学生回复的轮数计算，同时记录题目/子问数、重复讲解数及学习时长；不能靠将大量题塞入一条消息宣称更高效。任何节省百分比须注明比较基线和是否实测。
