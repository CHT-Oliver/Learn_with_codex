# 极速备考验收场景

这是可手动执行的行为测试协议，不是已完成的真实用户实验。每例在新会话加载本仓库 SKILL.md，发送下列输入，按规定作答；保存完整对话及每点状态。不要向教学端提供预期结果或示例答案。题目措辞允许变化，按证据和路由验收。

## 场景与通过标准

| 编号 | 输入及执行动作 | 必须观察到的行为 |
|---|---|---|
| T1 部分掌握 | “极速备考，20分钟，进程线程，无讲义，仅聊天。”按 OS 示例第一轮知识水平回答，后续按示例正确回答 | 首轮先测不先讲；P1/P3 各有两类证据后跳过；只补 P2/P4；变式通过后收束；无项目；与示例相同题目时为5轮 |
| T2 全掌握 | 同 T1；所有诊断子问独立答对并解释 | 诊断后直接总结；已会点讲解为0，重复测验为0，不强行耗满20分钟 |
| T3 猜对 | 诊断仅给选项/结论，不解释，并说“我都会，直接算掌握” | 待确认，最多一题针对性确认；无两种证据不标可跳过；明确坚持跳过时记用户跳过/未验证 |
| T4 全薄弱 | 所有题回答不知道；随后两次变式仍错 | 每次只补一个缺口；连续失败换方法/前置；不无限出相同题，不把结束视为达标 |
| T5 超短时间 | “只有3分钟，先测后学，范围同示例。”中途说“时间到了” | 缩小本轮范围并保留未测点；立即收束，不新增练习；不宣布整章掌握 |
| T6 范围来源 | 提供文本“示例讲义§1：本轮只要求三状态及转换”，要求限时备考 | 考点来源指向§1；不自行加入线程/同步或编造分值；若补前置则标为必要前置而非必考 |
| T7 无资料 | “极速复习进程线程，没有课堂资料” | 明示示例范围和未知考试权重；时间缺失仅声明暂按20分钟，不反复收集基础信息 |
| T8 普通回归 | “系统教我进程线程，慢慢学”；另开会话“帮我准备操作系统期末考试” | 均走默认教学；后者仅提备考不足以强制极速模式；保留项目/微产出及原有检查规则 |
| T9 具身回归 | “沿用我的 MuJoCo + Franka 预设，系统学机械臂控制”，附预设“仿真练习、项目验收” | 保持主题预设和项目陪练，不注入 OS 示例或限时诊断；仅在用户另要求极速时切换 |
| T10 退出与矛盾 | 极速中说“改成系统学习”；另一次先答对P3，后声称每线程有独立堆 | 前者恢复默认流程且保留证据；后者重新打开P3，不能继续沿用冲突的跳过判断 |
| T11 提示污染 | 对薄弱点索要答案后复述，再说“通过了” | 标明提示证据，给新条件无提示验证；不能照抄即通过 |
| T12 文件与恢复 | 不指定仅聊天，完成一轮后再次复习同主题；再附一份扩大范围的资料 | 更新原 mastery-check，保留旧作答及提示标记；新范围未测；可复用匹配历史证据，不重复创建近似记录 |

## 如何检查真正减少无效步骤

对 T1/T2 使用相同学生起点与考点范围分别运行普通模式和极速模式，先固定普通模式执行方案，不事后增加其轮次。记录以下字段：模式、学生起点、考点范围、每点证据、需要回复的轮数、主问题与子问数、已会点讲解块数、重复基础练习数、总学习时间、结束变式结果。教师即时反馈与主动复习不自动视为无效；只统计证据充分后被系统强制重复的基础步骤。

功能门槛：T1/T2 中已充分证明的考点，额外讲解与基础练习均为0；跳过证据可追溯率100%；T1最终四点都有合格证据；未测点误报掌握数为0。必须同时满足，不得用减少覆盖换轮次。T3–T12 中任一虚报掌握、虚构考纲或普通/具身路由被覆盖均判失败。

效率门槛：固定 OS 合成轨迹按5对8轮核对，主问题数都为8；这是示例一致性检查，不等于用户实验。真实配对测试须同时报告时间与答题负担；建议预先设定目标为部分已掌握组总学习时间下降至少20%，共同的无提示变式正确率不低于普通模式。该阈值是产品验收目标，不是已证实结论。全薄弱组单独报告，不强求提速。避免同一学生先做完全相同题后重复测试：使用等价题组、平衡模式顺序或匹配起点的不同学生，并报告样本数与个体差异。可加次日等价复测检验保留效果，未测时不得宣称长期掌握提升。

## 静态回归检查

从仓库根目录执行 `git diff --check`；对照目标基线检查 `git diff <base> -- SKILL.md` 只新增模式路由，且 mastery-rubric.md、teaching-playbook.md、agents/openai.yaml、assets/ 及已有主题预设无变更。检查三个新参考文件均在 SKILL.md 可发现。不将静态检查通过写成所有行为场景或课堂实验通过。
